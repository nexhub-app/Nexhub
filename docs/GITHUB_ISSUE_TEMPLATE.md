# GitHub Issue 固定格式模板（可复制）

> 当你无法使用仓库的 Issue 表单（例如通过外部渠道反馈），可直接复制下面对应模板到 issue 正文。
> 仓库已配置表单模板：点 **New issue** 后会自动按固定格式引导填写。

---

## 一、Bug 反馈模板

```
## 基本信息
- 应用版本：v0.4.0
- 运行平台：Android / iOS / Windows / macOS / Linux / Web
- 系统版本：Android 14 / Windows 11 23H2 ……

## 问题描述
（清晰、简洁地描述出现了什么异常）

## 复现步骤
1. 打开 ……
2. 点击 ……
3. 看到 ……

## 期望行为
（正常情况下应该发生什么）

## 实际行为
（和期望相比，实际多/少了什么、错在哪里）

## 日志 / 截图
（粘贴相关日志，可用 ``` 折叠；截图可上传。敏感信息请打码）

## 相关源 / 插件
（若与某个源有关，填写源名称，如 pms_m233 / dalvdm / 自定义源）

## 补充说明
（其他有用信息）
```

---

## 二、功能建议模板

```
## 相关痛点
（这个功能要解决什么问题？现有方案有什么不足？）

## 期望方案
（你希望怎么实现？越具体越好）

## 备选方案
（是否考虑过其他做法？为什么倾向上面的方案？）

## 影响范围
（涉及哪个模块：动漫/漫画/小说/影视/弹幕/源管理/设置/播放器 ……）

## 补充说明
（截图、参考链接、使用场景等）
```

---

## 三、文档补充模板

```
## 文档位置
（哪个文件、页面或章节？例如 README、docs/redevelopment/00_xxx.md）

## 问题或缺失
（文档哪里不清楚、有错误、或缺少内容？）

## 改进建议
（你希望怎么改？可以直接给出修改后的文字）

## 补充说明
（截图、参考链接等）
```

---

## 标题前缀约定
- Bug：`[Bug] 一句话描述`
- 功能：`[Feature] 一句话描述`
- 文档：`[Docs] 一句话描述`

## 提交前确认
- [ ] 已搜索现有 issue，确认不是重复提交
- [ ] 已注明应用版本与运行平台
- [ ] 已隐去账号、密钥等敏感信息
